# 新表盘设计方案：金属指针 / 图片 / 动画

> 2026-11-11。前置改动已落地：容器大基底、预览图深色边、预览块填满、构建器 `--base` 参数。
> 本文分三部分：**已完成的修复** → **新基底带来的能力** → **三款新表盘的设计方案**。

---

## 第一部分：本轮已修的两件事

### 1.1 预览图四周留深色边（修「长按大圆圈」）

**判断**：长按切换页显示的是**包内预览图**，不是表盘实时渲染。所以之前改 `scr` 的 `radius=0` 改错了对象。

**成因**：class 的预览图是**满幅**亮蓝渐变（`#071322 → #13314F → #071322`），整个 192×490 都被中蓝色铺满。跑道屏圆角极大，塞进遮罩后亮色区被裁成一个竖直大椭圆 —— 读出来就是"大圆圈"。而 clock 底色 `#0C0D10` 近黑，同样满幅、同样被裁，但深色和遮罩外看不出边界，所以"没有圆圈"。这正好解释为什么只有第一款有。

**修法**：`preview_style.inset = 16`，四周涂一圈深色（class 用 `#050C16` 深蓝、clock 用 `#05080C` 近黑），亮色区远离边缘。不是压暗四角 —— 上一版 `vignette` 把圆角半径按 `min(w,h)*0.28 = 53px` 估算，实际跑道屏圆角远大于此，所以越改越圆。

### 1.2 预览块填满，不再裸 `0x00` 填充

实测差异（这才是与官方的**唯一结构性不同**）：

| 包 | body 数据 | 块上限 | 尾部 |
|---|---|---|---|
| 官方 Lua Calculator | 39200 B | 39200 B | 填满 |
| 官方 Tic Tac Toe | 52988 B | 52988 B | 填满 |
| 我们（改前）class | 24050 B | 39200 B | **15150 B 的 `0x00`** |

新增 `shared/rle.py::pad_to()`，用**合法 RLE 指令**（`ctrl=n` + RGB，解出 n 个重复像素）精确填满到块上限。像素数据在 94080 之后，被裁掉，显示效果不变；但设备若按块长度硬解，读到的是合法指令而不是零流。

> 踩坑记录：`plen` 是**预览区总容量（含 8 字节头）**，body 上限是 `plen - 8`。第一次按 `plen` 填，直接触发 `assert len <= plen` 失败。

## 第二部分：新的大基底

### 2.1 新增 `base/band9-large.face`

从官方 `Tic Tac Toe` 包改来的基底，构建时用 `--base` 指定：

```bash
python3 build.py --face class --device band9                     # 标准壳 13616B
python3 build.py --face class --device band9 --base band9-large.face   # 大壳 17287B
```

| 基底 | lua 槽位 | 预览块 | 文件 | 用途 |
|---|---|---|---|---|
| `band9.face` | 13616 B | 39200 B | 53172 B | 轻量表盘（clock 用它，11110B 够用） |
| `band9-large.face` | **17287 B** | 52988 B | 126900 B | 复杂表盘（动画、多逻辑） |

class 实测：13568 / 17287，**余量从 48B 变成 3719B**（+77 倍）。

### 2.2 大基底的额外价值：**图片资源槽位**

`Tic Tac Toe` 包里除了 `lua/main.lua`，还有 **14 个 `lua/*.png` 资源块**：

```
lua/l_cpu.png  lua/l_draw.png  lua/l_po.png  lua/l_px.png  lua/l_you.png
lua/mode1.png  lua/mode2.png  lua/mode3.png
lua/nd0.png … lua/nd5.png
```

这是关键发现：**Lua 表盘能带图片**，不只是画文字和矩形。之前我们一直用 `Lua Calculator` 那个只有 `main.lua` 单槽位的极简壳，才产生"lua 表盘东西太少"的错觉。

官方其他包的规模也印证这一点：Flappy Bird 299KB（几百个鸟的帧）、Expenses 154KB（分类图标）、Stride 209KB。

## 第三部分：三款新表盘设计

### 共通：需要先做一次 API 能力探测

三款设计都依赖我们尚未验证的 LVGL 绘图能力。必须先跑一次探测表盘（约 30 分钟），确认这几个 API 在 Band9 固件上是否存在：

| 能力 | 猜测的 Lua 写法 | 用途 |
|---|---|---|
| 画线/多边形 | `lvgl.Line` / `lvgl.Object{...}` + `points` | 指针 |
| 圆弧 | `lvgl.Arc` / `lvgl.Object{radius, arc_width}` | 刻度环、进度环 |
| 旋转 | `obj:set{ transform_angle = 900 }`（0.1° 单位） | 指针转动 |
| 图片 | `lvgl.Image(obj, {src = "lua/bg.png"})` | 图片表盘 |
| 动画 | `lvgl.Animation` / `lvgl.Timer` + 重绘 | 动画表盘 |
| 位图缓存 | `lvgl.Canvas` / `lvgl.Image` + draw_buf | 高频重绘 |

**探测方式**：写一个 `faces/probe/main.lua`，逐个 `pcall` 尝试创建对象，把「成功/失败」直接显示在屏幕上（每项一行）。装一次就能看清哪些能用 —— 比翻文档可靠，因为这个固件并没有公开完整的 Lua 表盘 API 文档。

> 已知可用（实证）：`lvgl.Object`（含 radius/border/pad）、`lvgl.Label`、`lvgl.Font("MiSans-Demibold")`、`lvgl.Timer`、`lvgl.EVENT.CLICKED`、`lvgl.FLAG.EVENT_BUBBLE`、`io.open`、`os.execute`、`os.date`、`dataman.subscribe`。

### 方案 A：EV 金属（仿真指针表盘）· ID `882610320`

**目标**：像一块真实机械表 —— 金属拉丝表盘、立体指针、刻度环，且**依然带上课信息**（这是本产品线的铁律）。

#### 视觉结构（192×490 竖向跑道屏的适配）

跑道屏是高的，不适合做正圆表盘。两种构图：

**A1 上部圆盘 + 下部课表**（推荐）
```
┌─────────────┐  y 96
│   ╭─────╮   │  金属圆盘 ø150，居中
│   │  ◔  │   │  时针/分针/秒针
│   ╰─────╯   │  12 个刻度点
│             │
│   语文      │  科目（26px 暖白）
│  上课中 已上10分 │  状态（22px 琥珀）
│  下节数学    │  下节（20px 灰蓝）
│ EV Metal v1.0.0 │  署名
└─────────────┘  y 394
```

**A2 全屏表盘 + 底部浮层**：圆盘 ø280 撑满，课表信息半透明压在底部。视觉更冲击，但课表可读性差。先做 A1。

#### 金属质感的实现手段（不靠图片，纯代码）

| 质感 | 实现 |
|---|---|
| 拉丝金属底 | 圆盘内叠 40–60 条**极细水平线**（1px，交替 `#2A2E35` / `#3A3F48`），或用 3 层同心圆渐变 |
| 立体感 | 圆盘外圈加 2px 亮边（`#6B7280`）+ 内圈 1px 暗边（`#0A0C10`），形成浮雕 |
| 指针阴影 | 每根指针画两次：先画偏移 (+1,+1) 的深色版，再画本体 |
| 时分针 | 菱形/锥形：用 3–4 个 `Object` 拼，或用 `points` 多边形 |
| 秒针 | 1px 细线 + 末端红点（`#E5484D`） |
| 刻度 | 12 个短矩形，按角度放置；3/6/9/12 位加粗 |
| 中心轴帽 | 两个同心圆（ø12 深灰 + ø5 亮银） |

#### 旋转怎么算

若 `transform_angle` 可用：指针画在 12 点方向，之后 `angle = floor(deg * 10)` 设置。
若不可用：**退化方案**——每根指针预生成 60 个角度的位置表（`x_ofs/y_ofs`），定时器按分钟移动指针，用查表代替旋转。多花约 2KB 代码，但一定能实现。

#### 容量预算
- 纯代码方案：约 **9–12 KB**（含课表 core 约 3.5KB）→ 用大基底 17287B 宽裕
- 带阴影 + 刻度表：约 13–14KB → 仍在大基底内

#### 数据
- 时间：`os.date("*t", os.time())`，秒针靠 `lvgl.Timer` 每秒重绘（**注意耗电**，可降为 1 分钟一跳）
- 课表：`schedule_core`

### 方案 B：EV 光影（图片表盘）· ID `882610321`

**目标**：以**图片为主体**的表盘 —— 每天/每时段换一张背景图，课表信息压在上面。

#### 图片从哪来

大基底的 14 个 PNG 槽位可以**复用**：把 `lua/l_cpu.png` 等槽位的内容替换成我们的背景图，改名不用改（槽位名固定，内容可换）。或者自己造块。

#### 关键未知
1. 图片格式：槽位里是 PNG（现成的），但设备加载时是否需要转成 LVGL 的 raw 格式？官方包直接放 PNG，说明固件支持。
2. `lvgl.Image` 的 Lua 绑定写法未知（需探测）。
3. 尺寸：单张 192×490 RGB888 未压缩就是 282KB，PNG 压完约 20–80KB。**槽位容量必须 ≥ 图片大小**，超出就装不下。

#### 设计方案（B1）
```
上午（6:00-12:00）：晨光渐变 + 山影剪影
下午（12:00-18:00）：暖橙天光 + 云层
夜间（18:00-6:00）：深蓝星空 + 城市剪影
上课中：底部渐出一层深色蒙版 + 科目/剩余时间
```
3 张图 × 约 30KB = 90KB，加 lua 代码 → 需要一个 150KB+ 的壳。

#### 更省的替代（B2，推荐先做）
**不用整图，用图片做"装饰元素"**：只在圆盘/边框用 1–2 张小图（如金属纹理 8KB、天气图标 2KB），主体仍是代码绘制。这样文件仍能在 130–150KB 内，且不依赖大图解码性能。

### 方案 C：EV 流光（动画表盘）· ID `882610322`

**目标**：表盘有**持续或按事件触发的动效**，而不是静态画面。

#### 三种动效，按成本从低到高

| 动效 | 实现 | 成本 | 耗电 |
|---|---|---|---|
| C1 进度条呼吸 | 课程进度条颜色/透明度按秒渐变 | 极低 | 低 |
| C2 上课倒计时脉冲 | 距上课 <10 分钟时，状态行做亮/暗脉冲（2s 周期） | 低 | 低 |
| C3 粒子/流光 | 一束沿边缘移动的高光（用 2–3 个 Object 移动位置） | 中 | 中 |
| C4 逐帧动画 | 多帧图片按 Timer 轮播（如翻页时钟、下雨） | 高（图大、VM 慢） | 高 |

**推荐组合**：C1 + C2（纯代码，总共 <1KB），这对"上课提醒"这个产品定位是**真正有用的动效** —— 快上课时表盘会"呼吸"，比静态文字提示更容易被注意到。

> 重要：表盘**不能震动**（无 vibrator API），所以"提醒"只能靠视觉。脉冲/变色就是最接近提醒的视觉语言。这条限制反过来决定了：动效不该只做装饰，应该**服务于提醒**。

#### C4 的可行性警告
LVGL + Lua VM 逐帧重绘在 192×490 上开销不小，官方 Flappy Bird 能做到，但它是"全屏游戏、用户主动进入"；表盘是**常驻**的，逐帧动画会显著耗电。**不建议做常驻全屏动画**，要做也只在"抬腕后 3 秒内"播放。

## 第四部分：实施顺序与验收

| 阶段 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **P0** | 能力探测表盘 | `faces/probe/`，屏幕上列出可用 API | 装机一眼看清哪些 API 存在 |
| **P1** | 方案 A 金属指针 | `analog-band9-v1.0.0.face` | 指针走动准确、金属质感肉眼可辨、课表三行齐全 |
| **P2** | 方案 C 的 C1+C2 并进 A | 同上 +0.1 版 | 快上课时状态行脉冲可见 |
| **P3** | 方案 B2 图片装饰 | `photo` 或并入 A | 至少一处图片元素正常显示 |
| **P4** | 方案 B1 / C4（大图 / 逐帧） | 视需求 | 只在 P0 证明可行后才做 |

每款表盘必须遵守的**三条铁律**（踩过坑）：
1. `scr` 三件套：`radius = 0` + `clear_flag(SCROLLABLE)` + `add_flag(EVENT_BUBBLE)`（缺第三个 → 长按进不去切换页）
2. 课表数据段整体 `pcall` 隔离（数据异常只影响课表几行，不拖黑整块表盘）
3. 预览图四周留 16px 深色边（否则亮色表盘在切换页会变成一个"大圆"）

工具侧已就位：`check_profile_refs` 构建期硬校验（`P.*` 未定义直接失败）、`rle.pad_to` 填满预览块、`--base` 切换基底。
