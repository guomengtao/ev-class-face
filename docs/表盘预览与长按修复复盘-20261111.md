# 表盘「长按切换页缩略图变成大圈」修复复盘

> 日期：2026-11-11 · 项目：`ev/ev-class-face` · 涉及包：Band9-Analog v1.0.8 / v1.0.9
> 目的：把「核心错误是什么、怎么修好的、为什么修一个冒一个」写死在这里，避免下次再从错误的一层下手。

---

## 0. 一句话结论

看起来是**一个** bug，其实是**三个不同层**上的两个独立缺陷：

| 层 | 缺陷 | 症状 | 状态 |
|---|---|---|---|
| 容器层 | `.face` 包内预览块的 RLE 流被「假像素」填满槽位 | 系统设置里换表盘 / 长按切换页，缩略图退化成一个大圈 | ✅ 已修（commit `d6cd1c3`） |
| 事件层 | 装饰对象（方块）默认吃掉按下事件，不上抛 | 表盘界面长按只有**文字区**能换表盘，盘面/刻度/指针上长按无反应 | ✅ 已修（v1.0.9） |
| 内容层 | 配色、盘径、安全区 | —— 前三轮改的全在这一层，**与两个 bug 都无关** | 无须改 |

---

## 1. 先分清两条通道（这是前 5 轮打转的总根源）

同一个「表盘缩略图」，设备上有两条完全独立的链路：

```
① 系统设置 → 表盘更换 / 长按切换页
   读的是【包内预览图】：静态 192×490 RGB888，RLE 压缩，随 .face 一起装进表盘槽位
   —— 不跑 lua，不看你的渲染代码

② 表盘正在显示时的长按
   走的是【运行中的 lua 屏幕 + 系统事件】：手环 OS 检测长按 → 切到表盘选择器
   —— 与预览图一个字都不沾
```

所以：**改预览图永远不会影响长按，改 lua 也永远不会影响切换页缩略图。**

前三轮（class v1.0.13/14/15）反复调 `radius`、把盘面刷暗、加安全区遮罩，全在①的内容上使劲，
而缺陷在①的**封装**里 —— 症状自然一动不动。这条方法论后面单独成节（§5）。

## 2. 核心错误：预览块「解码像素数」超标 6~15 倍

### 2.1 合法形态

`.face` 容器尾部有一块预览槽位（`tail + 20` 起，长度 `plen`），结构是：

```
[8B 头: w, h, ...][RLE 流，填满 plen-8 字节]
```

**唯一合法判据：整块解码出来恰好 `w*h` 个像素（192×490 = 94,080），一个不多、一个不少。**

### 2.2 错在哪

`shared/rle.py` 里旧函数 `pad_to()`（commit `ef452ae`「预览块填满」引入）。
它的意图是对的 —— 官方包的槽位确实是写满的；但补法错了：用**重复指令**补：

```
ctrl(n) + 3B RGB = 4 字节  →  解码出 n 个像素（n ≤ 127）
```

于是每补 4 字节，解码器就凭空多读 127 个假像素；补 1.7 万字节 → 多出 100 多万假像素。

### 2.3 实测证据（33 个包全扫，规律干净得可怕）

| 包 | 解码像素数 | 比值 | 块尾空转字节 |
|---|---|---|---|
| **Band9-Analog-v1.0.8（用户看到的「大圈」）** | 1,223,239 | **13.00×** | 35,571 B |
| Band9-Class-v1.0.14（最初的「蓝大圈」） | 1,013,436 | 10.77× | 28,966 B |
| Band9-Class-v1.0.15（上一轮以为已修） | 344,778 | 3.66× | 7,896 B |
| Band9-Quartz / Oneline / Probe / Smash / TempControl | 55万~138万 | 5.9~14.8× | 1.4万~4万 B |
| 官方/第三方 TicTacToe、LuaCalculator、Monika×6、Stride、Flappy、Expenses、Daymatter 等 14 个 | **全部 94,080** | **1.00×** | **0** |

> 凡是我们 `build.py` 出的包 → 6~15 倍；凡是官方/第三方的包 → 恰好 1.00 倍、零剩余字节。

设备拿到十几倍的像素流，解码溢出 → **退回占位图形**，就是用户看到的那一个圈。
这也解释了老疑问：clock 为什么没有大圈 —— 它那块是 `pad_to` 之前用裸 `0x00` 填的，
`0x00` 正好被解码器当停止标记，像素数是对的（但结构仍与官方不一致，属于「碰巧没坏」）。

## 3. 修法：`encode_exact()` —— 像素数不许动，只把流撑满槽位

`shared/rle.py` 新增：

```
encode_exact(px, target_len, blksize=3) -> bytes
```

三步走，**全程不产生任何一个假像素**：

1. 先按最省方式编码，得到 `raw`；
2. 差 `D = target_len - len(raw)` 字节：把长 run 拆成多段
   （`ctrl(n) + 3B` 这种重复块，拆成 k 段就多出 `4(k-1)` 字节，像素数不变），
   拆到 `D` 能被 4 整除；
3. 剩下的 1/2/3 字节余数：挑一个 run 改写成**字面块**（`ctrl(0x80|n) + 3n 字节`），凑齐模 4 余数。

出口三重硬断言（不满足就抛错，绝不静默出包）：

```python
assert len(out) == target_len
assert decode_px_count(out) == (w * h, target_len)   # 像素数与流长度都精确
assert decode(out) == px                             # 整块还原 == 原图
```

配套改动：

- `pad_to()` **改成调用即抛错**，注释写明废弃原因 —— 防止有人再按旧习惯调它；
- `build.py` 出包后**回读自检**：预览块像素数 ≠ `w*h` 直接构建失败（构建期拦住，不靠人眼）；
- 新增 `tools/check_preview.py`：一条命令体检整个 `dist/`，自研包比值必须是 `1.00`。

### 修复前后（Band9-Analog）

| 项 | 修复前 | 修复后 |
|---|---|---|
| 预览块解码像素 | 1,223,239（13.00×） | **94,080 = 192×490（1.00×）** |
| 流占用 / 槽位 | 17,417 B + 35,571 B 假像素 | **52,988 / 52,988，零剩余字节** |
| 与官方包同构性 | 异类 | 与 TicTacToe/Monika 等 14 个包**完全同构** |

## 4. 第二个缺陷：长按只有文字区生效（事件层）

### 4.1 症状

v1.0.8 装好后：系统设置里换表盘 → 缩略图正常了 ✅
但表盘界面上长按：**文字区域**能进切换页，**盘面/刻度/指针/中心点**上长按毫无反应 ❌

### 4.2 根因

`main.lua` 里已经有这一行（v1.0.4 就加过）：

```lua
scr:add_flag(lvgl.FLAG.EVENT_BUBBLE)
```

但它是**必要不充分**的。lvgl 的事件命中规则是：

- `EVENT_BUBBLE` 加在**谁身上**，只表示**谁**的事件会往父级冒泡；
- 而按下的**落点是 hit-test 选中的最上层「可点击」对象**；
- lvgl 的普通 `lvgl.Object` **默认 `CLICKABLE = 1`**；
- 我们的盘面、12 根刻度、38 个指针方块、描边 —— 全是 `lvgl.Object`，全都默认可点击，**却都没加 `EVENT_BUBBLE`**。

于是：按下被最上层那块方块吃掉 → 事件到不了 `scr` → 系统收不到长按 → 无反应。

文字为什么例外？`lvgl.Label` 默认**不可点击**，hit-test 直接穿透到 `scr`（scr 可点击且已开冒泡）→ 长按正常。
**「文字能换、盘面不能换」正是这个机制的指纹**，看到这个组合就该直接怀疑 CLICKABLE。

### 4.3 修法（v1.0.9）

`faces/analog/main.lua` 加一个装饰对象统一出口，所有纯视觉对象建完立刻过一遍：

```lua
local function passive(o)
    pcall(function() o:clear_flag(lvgl.FLAG.CLICKABLE) end)   -- 不抢按下
    pcall(function() o:add_flag(lvgl.FLAG.EVENT_BUBBLE) end)  -- 万一被点到也上抛
    return o
end
```

`box()` / `label()` / 描边圆全部走 `passive()`（`grep -c passive` → 4 处：1 定义 + 3 调用点）。
`scr` 本身**保持可点击**，它是所有穿透事件的兜底落点。

### 4.4 验收（必须在真机上点满四个区域）

| 位置 | 期望 |
|---|---|
| 盘面空白处（无刻度无指针） | 长按 ~1s 进表盘切换页 |
| 刻度环（8 点/10 点方向上） | 同上 |
| 指针/中心橙点 | 同上 |
| 底部课程文字 | 同上 |

配一条静态检查（改完先跑，省一轮装机）：

```bash
grep -c "lvgl.Object(scr" faces/analog/main.lua    # 每个都必须在 passive(...) 里
```

## 5. 为什么会「修一个冒一个」——三层模型

这个项目已经连续三次出现「修好 A，B 立刻冒出来」。原因不是运气，是**跨层改**：
每一次只盯用户报的那个症状，而不是先定位它在哪一层。

| 层 | 这一层坏了会怎样 | 先验什么 | 手工验法 |
|---|---|---|---|
| **内容层** | 表盘长得不对（错位、糊、太亮） | `faces/*/main.lua` 的坐标/字号/配色 | 真机截图（带壳） |
| **容器层** | 缩略图不对、装不上、id/槽位错、包大小异常 | `tools/check_preview.py` + 构建自检 | 系统设置里换表盘看缩略图 |
| **事件层** | 长按/点击失灵、进不去切换页 | `EVENT_BUBBLE` + `CLICKABLE` | 真机在**盘面本身**长按 |

**铁律：症状出现，先问「这个症状属于哪一层」，再动手。**
判断口诀：

- 缩略图 / 装包 / 包大小 → **一定**是容器层，别去改颜色；
- 位置 / 字号 / 观感 → 内容层；
- 点不动 / 长按无反应 → 事件层，先查 CLICKABLE，再查 EVENT_BUBBLE。

历史教训（已推翻的旧结论，勿再沿用）：
`docs/表盘技术边界与class大圆圈分析-20261111.md` §3 曾判断「大圆圈不是代码 bug，是满幅亮色被圆角裁切」——
**错误**。当时改 `radius`、调暗底色、加安全区，全部无效。该文已在文首加勘误横幅。

## 6. 防重复清单（新出任何表盘，逐条打勾）

1. `python3 build.py ...` → 构建日志必须出现 `解码 94080px=192x490 ✓ 零剩余字节`；
2. `python3 tools/check_preview.py dist/Band9/*.face` → **自研包比值必须 1.00**（非 1.00 一律不出包）；
3. lua 里每个 `lvgl.Object(scr` / `lvgl.Label(scr` 都经过 `passive()`；
4. 真机 ①系统设置换表盘能看见正确缩略图；②盘面/刻度/指针/文字四处各长按 1 秒；
5. `ev-install -w 30 -v <包>` 回执为「安装成功」，且文件名是本批次的暂存名（防止拿旧记录冒充）；
6. **scr 永远不要 `clear_flag(CLICKABLE)`**：系统长按靠它命中，清了长按一起废（§10.3）。

## 10. Class 移除轻触切换背景（2026-11-11 晚，v1.0.17）

用户要求：Class 表盘「点击切换背景」这个功能去掉，保持默认一直纯黑。

### 10.1 删掉了什么

| 删除项 | 原本作用 |
|---|---|
| `THEMES` 数组（5 套：纯黑/深海蓝/暮光紫/松林绿/暖霞橙） | 配色候选池 |
| `theme_idx` | 当前主题索引 |
| `apply_theme()` | 运行时把颜色刷到 scr / 各 Label / 进度条 |
| `load_theme()` / `save_theme()` | 从 `THEME_FILE`（`/tmp/ev_face_theme.txt`）读/写索引 |
| `scr:onevent(lvgl.EVENT.CLICKED, …)` | 轻触 → 索引 +1 → 换底色 |

改为常量 `local th = { bg = 0x000000, time = 0xFFFFFF, accent = 0x7FD4FF, sub = 0xFFD479, hint = 0x8FB4D4 }`，
创建控件时直接取色，运行时不再刷配色。

### 10.2 为什么必须删 `load_theme` 而不是只改默认值

`THEME_FILE` 是**跨版本持久化**的：手环上存过 `n=3` 就永远是暮光紫，除非程序去读它。
只把 `THEME_FILE` 忽略掉不够——读者在就必须一起删。删干净之后，旧存档里的 2/3/4 全部失效，
不需要用户手动清 `/tmp`。

### 10.3 长按有没有被误伤（必查项）

**没有。** 两件事用的是不同事件：

- 轻触切换背景 = 应用层自己注册的 `EVENT.CLICKED`，已删除；
- 系统「长按进表盘切换页」= 系统层对**可点击对象**的长按，只要 scr 还是 `CLICKABLE`（`lvgl.Object` 默认即为 1）+ `EVENT_BUBBLE` 就成立，与有没有 CLICKED 回调无关。

因此这轮是「删回调」，不是「禁用点击」。以后若有人加回 `clear_flag(CLICKABLE)` 到 scr 上，长按会一起废——这条写进 §5 防重复清单。

## 11. Class 课程名占位「EV课程表」→ 日期 + 周几（v1.0.18）

用户要求：把表盘里的「EV课程表」文字删掉，换成日期和周几。

### 11.1 这行字是怎么冒出来的（不是写死在 UI 里的）

`l_subj`（课程名那行）初始占位是 `"EV课程表"`，但真正让它一直挂着的是数据层：

```lua
-- schedule_core.lua compute()
local out = { status = "今日无课", subject = "EV课程表", ... }   -- ① 默认值
...
if #today == 0 then out.next = find_next(); return out end        -- ② 今日无课：不改 subject
...
out.status = "今日结束"; out.next = find_next(); return out         -- ③ 今日结束：也不改 subject
```

**两个分支都不写 `subject`**，于是它老老实实保持默认值。所以只在 UI 那行改初始文本没用——
每 60 秒 `refresh()` 一次，就会被覆盖回「EV课程表」。必须**在赋值处**判断。

### 11.2 改法（只动表盘层，不动 shared）

```lua
local WEEK_CN = { "日","一","二","三","四","五","六" }
local function date_line()
    local t = os.date("*t", os.time())
    return string.format("%d/%d 周%s", t.month, t.day, WEEK_CN[t.wday] or "")
end

-- refresh() 内
if s.subject == "" or s.subject == "EV课程表" then
    l_subj:set { text = date_line() }     -- 占位 → 11/11 周三
else
    l_subj:set { text = s.subject }       -- 有课 → 语文
end
```

判断条件是 `"EV课程表"` 这个**占位值**本身，而不是 `status`：
这样「今日无课」和「今日结束」两个分支一次覆盖，将来数据层再加状态也不会漏。

### 11.3 为什么不改 `shared/lua/schedule_core.lua`

那里 `subject = "EV课程表"` 是 **EVFF 课程两行规范**的一部分，Analog/Quartz 共用同一份注入段
（文件里写明「改这里 = 所有表盘一起生效」）。用户只要求 Class，所以只在 `faces/class/main.lua`
做表盘层覆盖。要三款一起改，得先改规范文档再由 `make.py` 派生，不能就地改。

### 11.4 显示规则

| 状态 | 课程名那行显示 |
|---|---|
| 即将上课 / 上课中 / 课间休息 | 课名（语文…）—— 核心信息不让位 |
