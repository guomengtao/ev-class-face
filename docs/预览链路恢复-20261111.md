> **验收级别**：L2 端到端实机验证（Vela 模拟器 guest 内真实运行）· **结果**：**PASS**
> **时间口径**：北京时间 GMT+8，具体时刻带 `+0800`
> **实例**：仅默认 AVD `xiaomi_band`（小米手环 9 标准版，192×490 胶囊屏）；`evc-xiaomi_band-buddy-1` 全程未触碰；**从未 `adb reboot`**。
> **一句话结论**：链路没坏，是「宿主没常驻 + 包不完整 + EvFleet 票据 5 分钟硬上限把实例回收」三件事叠加。现在 **一条命令可出画**，且拿到 Lua 经 LVGL 真实绘制的运行帧与带机身外壳截图。

## 0. 先澄清名词：`miwear`（用户口中的「Mivier」）不是另一款模拟器

`miwear` 是 **Vela guest 内部的表盘宿主进程**，路径 `/bin/miwear`；不是 macOS 上的第二个模拟器，也不需要单独安装/启动一个「Mivier 模拟器」。
`ps` 里同时存在 `miwear_activity_service`（开机自起的活动服务，PID 19）与 `miwear`（表盘宿主主进程）。**只有 activity_service 不够**，必须把主进程前台拉起并常驻，才会去读 `watchface_list.json` → 加载 `market/<id>/lua/` → 执行 Lua → LVGL 画到 `/dev/fb0`。

用户说的「好像要先开 Mivier 才能预览」，翻译成技术动作就是：**`adb shell miwear` 前台常驻**。这一条是本次最关键的一步。

参考：`ev/ev-lua-mini-demo/Lua表盘-Mac模拟器出画成功经验-20261110.md`、`AstroBox-表盘预览能力分析-20261110.md`（后者结论：AstroBox 的「预览」只是展示作者上传的图片，**不是表盘渲染器**，不能替代本链路）。

## 3. 端口、时序、通道（照抄关键）

### 3.1 端口换算

`vela up` 起的是 `xiaomi_band-11000`，**serial = `emulator-11000`（控制台端口 11000），adb 端口 = 控制台 + 1 = 11001**。
（`emulator-5554` 是 AIoT IDE 默认实例的叫法；走 vela CLI 时是 11000 段，别按 5555 去连。）

| 项 | 值 |
|---|---|
| 实例 ID | `xiaomi_band-11000` |
| adb 目标 | `127.0.0.1:11001` |
| 屏幕 | 192×490，RGB565（bpp=2） |
| 一帧字节数 | `192 × 490 × 2 = 188,160` |
| 隔离 adb daemon | `-P 5038`（避开同机其它会话反复重启 5037） |

### 3.2 时序（**一秒都不能省**）

```
t=0      fleet request --shapes capsule        取票（5 分钟硬上限开始计时）
t=0      vela up xiaomi_band --wait ...        --wait 内部约 25s
t≈33s    sleep 22                             guest 完全就绪；<20s 拉宿主必失败
t≈55s    adb -P 5038 connect 127.0.0.1:11001  先 disconnect 11001/11003/11005 清残留
t≈57s    推包（resource.bin/preview.bin/config.json/uidmap.map/lua/*/watchface_list.json）
t≈59s    adb shell miwear  —— 必须是「当前 shell 的直接后台作业」，保留连接
         首次拉起有概率不常驻；脚本自动重试最多 3 次（实测第 2 次成功）
t≈73s    sleep 10~14                          等 LVGL 绘制
t≈87s    dd → pull → RGB565 解码 → 套壳 → 统计
t≈88s    fleet release                        归还票据
```

总耗时约 **90 秒**，远小于 5 分钟硬上限。

### 3.3 完整链路

```
watchface_list.json  type="1" / in_use="1"（其余 23 条 in_use=0）
        ↓
/data/app/watchface/market/167210065/
        ├── resource.bin   ← .face 副本，magic 5aa53412，bytes[5]=10，0x28 写 ID
        ├── preview.bin    ← 仅列表缩略图，不参与运行帧
        ├── config.json / uidmap.map
        └── lua/main.lua + main_theme1~3.lua   ← 纯 LVGL，零图片、零 reloader
        ↓
adb shell miwear（前台常驻；PID + miwear-pm / miwear-io / 渲染线程）
        ↓
Lua 解释器 → stdout 打印 EVFF_PREVIEW_LUA_ENTER / EVFF_PREVIEW_LOADED
        ↓
LVGL 绘制到 /dev/fb0（192×490 RGB565 = 188,160 B）
        ↓
dd if=/dev/fb0 of=/data/fbsnap.bin bs=188160 count=1 → adb pull → RGB565 解码 PNG
        ↓
vela.frame_in_place() 套 BAND 9 机身外壳（与 `vela shot` 同一套 skinframe）
```

**`type="1"` 是 Lua 开发盘专用标识**；`type=0` 会走内置盘路径，根本不加载 `lua/`。
**`bytes[5]=10` 是 ID 长度字节**：`.face` 原始头为 `5aa53412 0000...`，不补 10 宿主读不到 ID。

## 5. 失败排查表（下一会话照这张表查）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `adb devices` 空 / `vela ls` 无实例 | 上一轮票据超 5 分钟被 `ticket-hold-reclaimed`，`reconcile` 连带停机 | 用一键脚本（自己取票、90s 跑完、trap 归还）；不要手工多轮长期占票 |
| 2 | `ps` 只有 `miwear_activity_service` | `miwear` 主进程没拉起，或 `( cmd & )` 嵌套子 shell 退出后 adb 连接被回收 | **当前 shell 直接后台作业 + 保留 PID**；脚本已做三重重试，判据是 `miwear-pm` 在不在 |
| 3 | 首次拉 `miwear` 不常驻，第二次就好 | guest 显示服务初始化时序 | 保留重试，不要改成「一次失败就判平台不支持」 |
| 4 | 帧全黑（全 0）或纯白（1 色），但 stdout 有 Lua 堆栈/print | 别急着推「渲染链不通」 | 三信号交叉验证：宿主进程 / stdout / 取帧通道；1 色 = 宿主清屏后无内容 |
| 5 | 帧全黑且 stdout 0 字节 | 包不完整或注册错，`lua/` 没被加载 | 查 `type=1`、`in_use` 唯一、`resource.bin`、`lua/main.lua` |
| 6 | `type` 被改成 0 | 走内置盘路径，不加载 `lua/` | 注册表目标条目 `type="1"`，其余 `in_use="0"` |
| 7 | 缺 `resource.bin` / `bytes[5]≠10` / `0x28` ID 与目录不符 | 宿主识别不了这个盘 | 由 `.face` 复制并补 `bytes[5]=10`、把 ID 写进 `0x28` |
| 8 | 两个 `in_use=1` 并存（AOD `type=2` + 自定义盘） | 宿主选盘歧义 | 全表只留目标条目 `in_use=1` |
| 9 | `exec-out dd if=/dev/fb0` 返回 `error: closed` / 0 字节 | NuttX `dd` 不支持该通道 | `dd ... of=/data/fbsnap.bin bs=188160 count=1` → `adb pull` |
| 10 | 解码出来是左右重影/颜色错乱 | 把 bpp 当 4 了；本机 `xiaomi_band` 是 **RGB565 bpp=2** | 一帧固定 188,160 B；`dd bs=376320` 会读到两帧 |
| 11 | `nsh: ls: argument invalid` / `grep`/`head` 找不到 | NuttX 精简命令集 | 用 `ls`（不带 `-la`）、`cat`、`dd`、`ps`；过滤一律在 host 侧做 |
| 12 | 推包推到别的实例 | adb 端口残留 | 端口 = serial+1；先 `disconnect 11001/11003/11005` 再只连当前；用 `-P 5038` 独立 daemon |
| 13 | `vela up` 被拒「无票据」 | EvFleet 票据闸 | 先取票，用完归还 |
| 14 | `vela down` 后新票一直排队 | 实例被标 `intruder` | `vela reap` 清理后再申请 |
| 15 | 在 zsh 里写 `ADBC="$ADB -P 5038"; $ADBC ...` 报「no such file or directory」 | **zsh 默认不做单词拆分**，整串被当成一个命令 | 脚本 shebang 是 bash；交互式 zsh 里请写全 `$ADB -P 5038` |
| 16 | `adb reboot` 后实例直接消失 | qemu 上 reboot = 终止进程 | **禁用**；重载只走 `vela down` + `vela up`（`/data` 持久保留，不必重推包） |
| 17 | 带壳截图被后续失败清掉 | 同名产物覆盖 | 成功立刻 `cp` 另存到 `docs/screenshots/` |
| 18 | 误以为 AstroBox 能预览 Lua 表盘 | AstroBox 的 preview 只是 `<img src>` 展示作者上传图片 | 真实运行帧只能走本文链路；AstroBox 的价值在 BLE 安装/切换 |

5. **Lua 脚本是最小验证骨架**（纯 LVGL、无图片、无 `dataman`）：中文/字体/数据订阅/时间刷新未在本单验证。
6. **未改动任何别人的包**：只新建 `tools/`、本 `docs/` 文档与 `docs/screenshots/EVFF-Preview-*` 取证图；`faces/`、`shared/`、`build.py`、`devices/`、`dist/` 全部只读。
