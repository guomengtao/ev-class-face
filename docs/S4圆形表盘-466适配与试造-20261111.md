# S4 圆形表盘（466×466）适配与试造

> 2026-11-11 22:05 +0800 · 对应产物 `dist/S4/EV-Quartz-R-S4-v1.0.14.face`

## 1. 背景

EV Quartz 原来只做 Band9（192×490 跑道屏）。小米手表 S4 是 466×466 圆屏，
要做一款同血统的圆盘（竖排双行时间 + 课程联动）。

## 2. 结论先说：跨机型不需要"官方基底"也能起步

查证结果推翻了一个常见误解：

| 曾经的判断 | 实际情况 |
|---|---|
| `.face` 里写死 deviceType，必须拿官方包 | **包里没有 deviceType**。`devices/*.json` 里的 `device_type` 字段全仓库无任何代码引用，只是档案文档 |
| 分辨率写死在头部 | 分辨率只有两处作用：`lvgl.HOR_RES()/VER_RES()`（lua 运行时取，天然动态）与**预览块**的 w/h 字段 |

真正锁死设备兼容性的只有**预览块**。表盘本体（lua 渲染）跨机型无感，
因为 `faces/*/main.lua` 第一行就是 `local W, H = lvgl.HOR_RES(), lvgl.VER_RES()`。

**不入库**，原因见第 5 节。

## 4. 构建

```bash
# 出包（预览块等长保留，只注入 lua）
python3 build.py --face quartz-round --device s4 \
  --base band9.face --allow-preview-mismatch --no-preview --no-bump \
  --out dist/S4/EV-Quartz-R-S4-v1.0.14.face
```

`--allow-preview-mismatch` 是本次新增的开关：允许基底预览尺寸（192×490）与机型屏幕（466×466）不一致，
跳过构建器的尺寸断言。**只做跨机型试造用，正式版应换成 S4 官方基底。**

## 5. 三个真机踩坑（重要，别再犯）

### 5.1 预览块绝对不能自己重编

试造时把预览块从 192×490 重编成 466×466，真机表现是**卡顿 + 重启**。两个独立原因：

1. **解码 buffer 需求暴涨**：466×466 = 217,156 px × 3 B = **651 KB**，而 Band9 只要 282 KB。
   这块 buffer 由固件分配，越界即重启（NuttX 无 MMU 保护）。
2. **预览头字段没同步**：预览块前 8 字节 `e021a55a 03 e84400`，除 magic + blksize(3) 外
   还有 3 字节长度/块数信息。尺寸改了却沿用基底旧值，解码器按错长度读 → 直接读到流外。

**正确做法**：`--no-preview` 等长注入，预览块与基底**逐字节相同**。
验收方法：比对包长与基底一致、`data[tail:]` 二进制相等。

### 5.2 字号不能按屏幕比例线性放大

Band9 时间字号 44 px，按宽度等比 466/192 推得 107 px —— 这个推论是错的。
MiSans 一个 104 px 中文字的抗锯齿位图约 5.4 KB，十几个字常驻数十 KB，
NuttX 小内存下会反复重排 → 卡。当前取 **88 px** 为折中。

### 5.3 圆形屏排版必须按弦宽校验

圆内任意高度 y 处的可用宽度：`w(y) = 2√(R² − (y−R)²)`，R = 233。

不校验的后果：底部三行（科目 / 状态 / 下节）会被 6 点方向的弧切角。
`devices/s4.json` 的每一行都跑过这个公式，构建时也要复核。

实测各行的上下沿宽度都留有余量，其中最紧的是底部品牌行（13 px，需 132，可用 179）。
