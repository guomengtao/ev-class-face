# 开发方案：视觉系课程表盘（Codename: EV Aurora）

- 日期：2026-11-12 08:30 +0800
- 状态：方案待 Tom 确认后开工
- 依赖：`shared/face_container.py` / `shared/rle.py` 字节级组包链路（已验证可用）

## 1. 目标与差异化

现有 4 款守护表盘：class（信息面板）、clock/Quartz（竖排石英大字）、analog（指针）、oneline（单行）。全部走内置字体，无一有视觉层。

**EV Aurora 定位：第一款"看得见的"表盘**——整屏插画背景 + 艺术字形图片数字 + 课程信息层，拉开与现有 4 款的观感差距。

## 2. 壳选型（实测结论，2026-11-12 逐字节核验）

| 壳 | 总大小 | 关键槽位 | 结论 |
|---|---|---|---|
| **Daymatter（选它）** | 201744B | `_lua/daymatter/bg9.png` **145528B**（整屏背景）+ lua 14369B + 0-9 数字图 10 张（276~730B/张） | ✅ 结构就是"背景+图片数字"，现成范例 |
| Smash/TicTacToe | 126900B | lua 17287B，PNG 全部 ≤1581B | 塞不下整屏背景，弃 |
| Quartz 现壳 | 53172B | 仅 lua 13616B，无图片槽 | 不可能做视觉，弃 |

ID 策略：沿用 Daymatter 壳原 ID `9798252660` 或换新 ID（二选一，装机时定；切换页蓝圈是固件层已知问题 pit-20261111-170，与本方案无关）。

## 3. 素材清单（开工第一步先产这个）

| 素材 | 规格 | 生成方式 |
|---|---|---|
| 背景图 1 张 | 192×490，≤140KB（RLE/PNG 二选一，装机实测定） | AI 生图 + 手动压色板 |
| 数字 0-9 共 10 张 | 统一字形高度（建议 48~64px 高），单张 ≤1KB | 选定字体→渲染→逐字裁切 |
| （可选）分隔冒号 1 张 | 同数字规格 | 同上 |

背景设计方向（Tom 挑一个）：A 极光/星空渐变；B 纸质手账/课程表贴纸风；C 暗色几何极简。

## 4. Lua 架构

参照 Daymatter 原版 lua 改造，布局三段：

```
背景整图（lvgl.Image, bg）
  ├─ 时:分 图片数字（lvgl.Image × 4~5，逐位贴，位置每分钟重算）
  ├─ 课程提醒层（内置 MiSans 文字，Tom 2026-11-12 明令必备，与其他表盘一致）：
  │     上节课 · 时间+课名
  │     当前课 · 上课中 + 课名（视觉最大）
  │     下节课 · 时间+课名
  └─ 版本水印（v1.0.0）
```

设计稿：`EV_Aurora_设计稿_v2_合规版`（2026-11-12 08:52 修正），两方向待 Tom 拍板：
- 方案 A 极光星空（深色） / 方案 B 纸质手账（浅色），同一版式。

**ev-six / v5 可读性铁律（Tom 2026-11-12 08:49 指出 v1 稿字号违规，本节为硬约束）**：
- 字号只有 **44/30/28/24 四档**，24px 绝对下限，24px 以下禁用（v1 稿 11/12/15px 全部作废）；
- 单行 ≤6P（≈6 汉字宽），7P 硬极限仅限 24px 整行；`·` 点税 1.1P；
- 留白税：页面 padding 12px，卡片 padding ≤8px，留白只从纵向买；
- 禁徽标/分隔符/导航箭头，状态用底色层次表达。

版式（192×490 实排）：
```
周三 11月12日        24px（日期）
10:14               图片数字 ~72px 高
[上课中]            24px 底色块（状态层）
数学                44px（当前课，全屏最大文字）
上 语文 08:00       24px（上一节）
下 英语 13:30       24px（下一节）
v1.0.0              24px（版本水印）
```
取舍说明：24px 下限下无法再塞"今日剩余节数"等附加行；上/下节课用「上/下」单字前缀+时间+课名压进 6P。深色稿课程区文字在 AI 背景图上需保证对比度（背景对应区域压暗处理）。

- 时间跳变时只 `set_src`/`set_x` 换数字图，不重建控件（Daymatter 原版即此写法，省内存）。
- 课程数据沿用现有 class 系的数据源接入（与 Quartz 同一套逻辑，复用其取课函数）。
- lua 预算 14369B：取课逻辑约占 6~8KB（照搬 Quartz），贴图布局约 3KB，余量充足。

## 5. 组包与验证流程

1. `face_container` 打开 Daymatter 原版包 → 清空 0-9 槽，写入新数字图；
2. 替换 `bg9.png` 槽为新背景（RLE 往返校验必须过）；
3. 替换 `daymatter.lua` 为新逻辑（槽 14369B 内等长或更短，`pad_to` 补齐）；
4. `set_identity` 定 ID/名称 → 输出 `dist/Band9/Band9-Aurora-v1.0.0.face`；
5. 模拟器验证：`ev/ev-emubuddy` 装 `xiaomi_band` 默认实例跑 24h 时间跳变；
6. 真机：AstroBox 投喂（`ev-install.sh`），Tom 前台抽验运行画面 + 切换页。

里程碑：素材定稿 → v0.9 模拟器跑通 → v1.0.0 真机交付，预计 1 个工作日内（素材 AI 生成当天出）。

## 6. 风险与已知边界

- **背景图格式兼容**：Daymatter 原版 bg9.png 是什么 PNG 变体（色深/调色板）需先解析照抄，固件可能只认特定编码 → 开工第一步先 dump 原图头复刻。
- **切换页蓝圈**：固件层已知问题（pit-20261111-170），所有自研 Lua 盘皆有，不影响运行，不纳入本方案验收。
- **容量红线**：背景 >145528B 会爆槽，AI 出图后必须压色板/降色深。
- 并行会话占用：本方案只新增 `faces/aurora/` 目录与新 dist 产物，不碰 `build.py`/`shared` 原件。

## 附：安卓同步器"用户传图换背景"可行性（只沟通，本期不做）

**结论：能实现，中等复杂度，且我们的组包链路已经把最难的一半做完了。**

链路拆解（现状 vs 缺口）：

| 环节 | 现状 | 缺口 |
|---|---|---|
| 用户选图/裁切 | — | Android 端 UI（选图 + 192×490 裁切框 + 预览），1~2 天工作量 |
| 图片转包内格式 | Python `rle.py`/`face_container` 已验证注入可行 | 需把"任意图→合规尺寸→压缩到 ≤145KB→注入 bg 槽"串成一条命令；**若要在 Android 端本地做，需把这套 Python 逻辑移植成 Kotlin/轻量 C**，或者更省力：图上传到电脑/服务端转换后回传 `.face` |
| 装机下发 | AstroBox/同步器链路已有 | 无缺口，换图=重打整包下发 |

**两个关键判断**：
1. 技术上不难——换背景本质就是"字节级替换包内一个文件槽"，我们已实证（预览注入成功过）。复杂度集中在 Android 端的图片裁切 UI 和格式转换工具移植。
2. 真正的风险是**真机格式兼容**：固件是否接受任意来源的背景 PNG/RLE，必须先拿一张自选图真机验证（一次实验），这决定 Android 端转换器的规格。

**排期口径（Tom 2026-11-12 确认）**：换图功能整体后置——先把安卓同步器做完，再对接"用户传图换背景"。本表盘 v1.0.0 不预留该功能，仅要求素材槽位结构清晰（bg 槽独立、数字槽独立），为后期对接留好接口。
